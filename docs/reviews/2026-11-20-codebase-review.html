What is solid

  • Step answers, hints and hidden tests stay in server-side secret. reveal checks the step state first, and publicDoc strips game answers.
  • The attempt state machine locks the progress row, and a partial unique index allows one observed attempt per step.
  • The spend ledger uses an advisory lock, and production refuses to start AI without a spend cap.
  • Docker code runs have no network, a read-only root, all capabilities dropped, and pid, memory and CPU caps.
  • The engine token is compared in constant time, request bodies are capped, and every LLM call has a deadline.
  • Workflows pin actions to a SHA and use least-privilege permissions. The reviewer reads REVIEW.md and AGENTS.md from base.
  • Migration 0023 is safe on a populated database. The xstate step machine enforces predict-before-reveal in the web app.

Product and learning logic

Two more reviewers checked the idea itself against what the app does: one for product coherence, one for the adaptive learning loop. The short version: the code quality is fine, but the product does not yet do what its docs say. The predict, mastery and next-lesson loop exists, yet a learner on the main path never reaches it.

What doesn't make sense, ranked

  1. CORE AI paths skip the core loop. The outline enum (ai/service.ts:34) never produces predict, and only predict lessons create steps and attempts. The Home Generator is the main way in, so its learners never predict, never use the hint ladder and never move their mastery. Confirmed.
  2. CORE Mastery drives nothing the learner sees. Nothing in apps/web calls me.next or me.mastery. Continue is the first unfinished lesson in course order (home.ts:137). Locks open on completion, not mastery. explanationStyle, skipOffered and hint depth exist only in the plan. missedConcepts is always []. Even so, Landing says "the next lesson adapts to what you know". Confirmed.
  3. CORE "Done" is not "learned".
    • Learn and watch lessons complete on open (LiveLesson.tsx:26).
    • Predict lessons complete when every step is revealed or skipped, even if every answer was wrong.
    • One game completes a game-practice lesson.
    • A scrim lab completes without its gates.
    So progress bars measure exposure, not learning. Confirmed.
  4. LOGIC No remediation. The policy only considers concepts in unfinished lessons (policy.py:154). A learner at p=0.5 on a "done" lesson gets ADVANCE with the reason "You've mastered everything so far", which is false. Confirmed with a script.
  5. LOGIC Most lesson kinds produce no evidence. Only predict attempts feed BKT. Games, sandbox checks, learn, watch and Sloppy record nothing. Confirmed.
  6. LOGIC Concepts are over-credited and prerequisites are empty. Steps fall back to every concept in their lesson, so 3 correct MCQs push two concepts from 0.2 to 0.967, past the mastered threshold. edges: [] is always sent (mastery.ts:138), so unlocking and the PRACTICE branch can never run. Confirmed.
  7. LOGIC XP and streak disagree with mastery. A hinted correct answer earns 10 XP but counts as wrong for BKT. The streak counts only predict attempts, so a learner on an AI path can never build one. Sandbox practice earns nothing. Confirmed.
  8. LOGIC Observations are dropped silently. A non-transient engine error still sets masteryAppliedAt (mastery.ts:269). p_guess is 0.25 for 3-option MCQs where it should be 1/3. Concepts are per world, so "functions" is tracked twice. Confirmed.
  9. SCOPE Off-mission scope. The outline prompt says "school and practical subjects… Code is one subject among many" (prompts/outline.md:1), and the Generator is headed "Learn anything". Confirmed.
  10. SCOPE The headline feature isn't built. "Real code changes, replayed" is on Landing and in idea.md, but commit ingest throws "not available yet (WP6)" (imports/ingest.ts:6). Confirmed.
  11. SCOPE Sloppy doesn't know the lesson. Its prompt is fixed to "the Tiny Task Tracker CLI" (INSTRUCTIONS.md:1), and the request carries no lesson, task or concept. Confirmed.
  12. AUDIENCE Teen privacy and incentives. The leaderboard is public by default, there is no age gate at signup (NFR1), and the engagement layer rewards activity over learning. Confirmed.

What would most improve learning

  1. Put a prediction in every kind. Each learn, watch and game lesson opens with an mcq or cloze step and completes on an attempt, not on open. This alone makes BKT and the streak work for AI paths.
  2. Put mastery in charge. Render me.next with its reason as the Continue card and on the lesson-end screen. Unlock by p_known. Pass real missedConcepts into generation.
  3. Remediate. The policy includes weak concepts from finished lessons and recommends review or practice. The ADVANCE reason names only concepts that are actually mastered (as a property test).
  4. Write the JS/TS concept catalogue with prerequisite edges (variables, conditionals, loops, functions). Require concepts per step, and send edges to the policy.
  5. Measure an outcome. A pre-test and post-test per concept on the seeded demo set. Add a small spaced-review queue (review_schedule, plan §7). Run S2b.

Fix plan

One concern per PR, as AGENTS.md requires. ◆ sensitive marks a PR that touches a SENSITIVE path, so it needs a clean pnpm review --json from a model other than the author's before agent:merge. Every PR runs pnpm agent:verify against a test Postgres before it is pushed. A bug fix starts with a failing test (a property test for an invariant). Wherever a mistake could happen again, the PR adds a check before any prose rule.

Phase 0: sync (before anything else)

  1. Rebase local main on origin/main, which is 7 commits ahead. Move 5eb3fcd onto a branch, add !.env.example to apps/web/.gitignore, and open it as a PR (1 PR).
  2. Recheck each finding below against the new head and drop any that are already fixed.

Phase 1: close the merge-gate holes ◆

This comes first because every later PR goes through the gate.

  1. Gate runs from base: load merge-gate.ts and its imports from origin/main, or make it a required CI check. Remove --skip-local, or allow it only with --dry-run. Add tests for both.
  2. Trust the review result: the gate checks that reviewer ≠ author and makes --author required. A truncated diff returns incomplete. Either the gate runs the review itself or the result is signed. Fix the example in docs/agents/review-pipeline.md.
  3. Widen SENSITIVE: add all of scripts/, games/grade.ts, attempts/machine.ts, dev/route.ts, guide.py, bkt.py, policy.py, learner.py, mastery.ts, app.ts, **/package.json, e2e/scripts/, pnpm-lock.yaml and apps/api/test/helpers*. Add a test that lists the expected sensitive files.
  4. Guardrail escapes: replace the *.gen.ts and *.generated.ts patterns with the exact generated path. Have the boundary check scan .js and .mjs and reject template-literal imports. Add scripts/tsconfig.json and include it in lint:types.

Phase 2: privacy, safety and core principles

  1. ◆ Leaderboard: a migration sets leaderboard_opt_in to default false and backfills existing learners to false. Show a generated handle, never the email local part. Add a test that no email-derived string appears in the home.get leaderboard. Ask the owner about the backfill.
  2. ◆ Scrim reveal on the server: lessons.get returns segments only up to the first gate that isn't revealed or skipped. Lesson completion requires every gate to be revealed or skipped. Add a property test: no segment after an unrevealed gate is ever serialized.
  3. player-core scrim:
    • Reject non-finite or out-of-range at, durations and segments in buildScrimTimeline.
    • Clamp at to the segment.
    • runCrossed returns an array.
    • Gate keys come from the step id.
    • Derive the file name from the language.
    • Widen the generators and add a "part gate blocks later edits" invariant.
  4. ◆ Sloppy guardrails: the guide route calls assertAiEnabled, reserveAiSpend and isSafeText and gets a short timeout. A deterministic output check rejects code fences and code-like lines, then repairs or refuses. The reply returns only guide. Add tests for a jailbreak-shaped input and the kill switch.
  5. ◆ Engine leak check: cover prompt and explanations.practice, and mirror the check in the API zod schema.
  6. Owner decision, then fix: AI auto-publish. Either add a draft and approve flow, or record the exemption for private self-generated paths in AGENTS.md and docs/plan.md.

Phase 3: broken learner flows

  1. ◆ Daytona checks: add runChecks to the sandbox backend interface and implement it for Docker and Daytona. Add a test that /sandbox/check uses the configured backend. Use the lesson's language, not the client's. Give Daytona shell sandboxes networkBlockAll, resource limits and timeouts. Truncate output after appending.
  2. Scrim until the player exists: remove scrim from the AI outline enum, or validate gates in validatePart. Seed the demo world as private. LiveLesson shows "Not playable yet" with no retry.
  3. Practice workbench:
    • Add visible Run and Lint buttons and fix the empty-state copy.
    • Remove showPlanned from the lesson route.
    • Keep one AIGuide instance that receives the selection, lint and video prompts.
    • Hide the Watch tab unless lesson.media exists.
    • Reset the result when the code changes.
    Check it in the validator, and add or extend an e2e test.
  4. ◆ Game completion: mark a game-practice lesson complete only when all its blocks are done. Strip games from learn docs, or render them read-only. Add an attempt limit and a hint ladder to games.check and games.hint.
  5. Account error state: show an error and a retry when home.get fails. Use a router link in Notice.

Phase 3b: make the learning loop real ◆ learner model: owner sign-off first

AGENTS.md says changes to the learner model need the owner. Agree the direction first, then ship these as separate PRs.

  1. Concept catalogue: variables, conditionals, loops and functions with prerequisite edges, in one shared namespace across worlds. The seed validator requires concepts on every step, and mastery.ts sends manifest edges in place of [].
  2. Prediction in every kind: the outline adds a leading mcq or cloze step to learn, watch and game lessons, and generation for predict is re-enabled. Learn and watch lessons complete on reaching the end, not on open. Add a property test that no lesson completes without an observed attempt.
  3. Evidence from every kind: games, sandbox checks and scrim gates call observationOf on the first try, each with its own guess rate (p_guess = 1/options). A failed observation is retried, not marked applied.
  4. Remediation: the policy considers weak concepts in finished lessons and returns REVIEW or PRACTICE. The ADVANCE reason names only mastered concepts. Add a property test.
  5. Show it: me.next becomes the Continue card and the lesson-end screen, with its reason. Course locks use p_known. Real missedConcepts go into generation.
  6. Honest progress: XP and streak follow observed learning (the hint rule, mastery gains). Sandbox passes count. Add a small spaced-review queue.
  7. Sloppy with context: pass the lesson id, task, concept and hint rung, and drop the hard-coded "Tiny Task Tracker" prompt. Record Sloppy use as a hint-like signal.
  8. Scope cleanup: make the outline prompt programming-only, remove "Learn anything" copy, and make Landing claim only what ships (no "real code changes" until ingest exists). Update docs/plan.md, the AGENTS open-work list and the feature map in the same PRs.

Phase 4: reliability and performance

  1. ◆ Mastery transaction: call the engine before the transaction, then write the results in a short one. Owner call: wire me.next into Home, or stop calling /v1/next.
  2. Timeouts: send the API's outline deadline to the engine in a header so the engine stops when the client gives up. Add one transient retry on 429 or 5xx.
  3. ◆ Seed: the upsert includes status, steps are matched by (version, idx), and removed steps are deleted. Seeding narration becomes an explicit option.
  4. ◆ Schema hygiene: add FK ON DELETE CASCADE for learner-owned tables. Add a Postgres healthcheck in compose.
  5. Bundle size: lazy-load the blocks in blocks/registry.ts and each view in LiveLesson. Limit Monaco to JS, TS and Python. Memoise the palette and context, and don't mount hidden AIGuides.
  6. ◆ Reproducible build: take the changelog fetch out of prebuild. Make it a manual script, or declare the file as a turbo output.
  7. Moderation: put an interface over the provider so it runs through LiteLLM or a pluggable endpoint.

  3. ◆ Tooling: merge the three bin.ts files into one shared module. Remove the stale REVIEW.md:31 line and the agent-review.ts:69 path.
  4. Owner decisions, then delete or wire:

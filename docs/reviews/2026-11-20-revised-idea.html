2. The idea, restated

LearnSlop teaches programming concepts to beginners through short lessons that always make you predict before you see. Each answer is evidence about one concept. A learner model (BKT, per learner and concept) turns that evidence into the next thing to do, and the app says why.

The loop

3. Rules for each lesson kind

Every kind follows one rule: predict first, observe the first try, complete on evidence. The table says how each kind meets it.

KindPredictionEvidence to BKT (first try only)Completes whenp_guess
predictEach step (mcq or cloze)Each step's first attempt; a hint before it counts as incorrectEvery step has an observed attempt and is revealed. Skip-only is not complete.1/options; cloze 0.10
learnAn opening mcq on the doc's idea, before the doc showsThe opening step, plus a closing check stepThe closing check is attempted1/options
watch"What will this change do?" before playbackThe opening step, plus the closing checkThe closing check is attempted1/options
practice"Which output do you expect?" before RunThe first /sandbox/check result per conceptHidden tests pass0.05
game-practiceBuilt into each game roundEach block's first checkEvery game block is completeper game kind
scrimGate mcq before the segment after itEach gate's first attempt, plus the first lab checkEvery gate is revealed and the lab passes1/options

XP: XP is awarded for an observed correct first try with no hint, and for a lab or game that passes. Streak: a day counts once the learner has 3 observed attempts of any kind, so learners on generated paths can build streaks. Server side: the server never sends a segment, hunk or doc section that comes after an unanswered gate.

4. Learner model changes

These change the learner model, which AGENTS.md says needs the owner. The owner asked for this work, but each PR is still sensitive and goes through review.

  1. Concepts per step are required. The seed validator and the AI outline reject a step with no concepts, and the lesson-wide fallback in mastery.ts is removed. This stops three correct MCQs mastering two concepts at once.
  2. Edges are real. Manifests declare edges from the catalogue, and mastery.ts sends them in place of edges: [], so unlocked() and the PRACTICE branch do work.
  3. Remediation. policy.py candidates include concepts from finished lessons with p_known < 0.8, which get REVIEW (re-serve, or generate a short predict lesson). Add a property test: an ADVANCE reason never names a concept below the mastered threshold.
  4. p_guess = 1/options for mcq, set per step. It is currently 0.25 for 3-option questions.
  5. No lost evidence. A non-transient engine error leaves masteryAppliedAt null and records the error, and the next read retries.
  6. The engine call happens outside the transaction: read inside it, call the engine, then write in a short transaction, so a slow engine can't hold the 10-connection pool.
  7. The recommendation is used. me.next drives Continue, and course locks use p_known. POLICY_VERSION parity then protects something real.
  8. Sloppy feeds the model. A Sloppy request while a step is open is recorded like a hint rung on that step, so a correct answer after it is not observed as correct.

One concern per PR. ◆ marks a sensitive path, which needs a clean pnpm review --json from a different model before agent:merge. Each fix starts with a failing test (a property test for an invariant) and adds a check before any prose rule. Every PR also runs agent:verify against a test Postgres.

Phase 4: make the learning loop real ◆

  1. Catalogue (§2) with edges, global concept slugs, and the seed validator requiring concepts on every step. Add a js.conditionals seeded lesson.
  2. Evidence from every kind: games, sandbox checks and scrim gates call observationOf with the right p_guess. Failed observations are retried.
  3. Policy remediation, a true ADVANCE reason, and p_guess = 1/options (§4.3, §4.4), all with property tests.
  4. The engine call moves out of the transaction (§4.6).
  5. Show it:
    • me.next is the Continue card and the lesson-end screen, with its reason.
    • Course locks use p_known.
    • The mastery list is on Home.
    • Real missedConcepts go into generation.
  6. XP and streak follow §3.
  7. Measurement: a pre-test and post-test per concept on the seeded demo set, recorded as attempts with no new data. A small spaced-review queue (review_schedule, plan §7).

Phase 5: Sloppy and AI safety ◆

  1. The guide route calls assertAiEnabled, reserveAiSpend and isSafeText, and gets a short timeout.
  2. A deterministic output check rejects code fences and code-like lines, then repairs or refuses. The reply returns only guide (no usage.model).
  3. Lesson context: the request carries the lesson id, task, concept and hint rung, and the fixed "Tiny Task Tracker" prompt is removed. Each use is recorded as a hint rung (§4.8).
  4. The web app keeps one AIGuide instance, which receives the selection, lint and video prompts.
  5. Moderation goes through a LiteLLM-compatible interface.
  6. The outline deadline is sent to the engine, and the engine adds one retry on 429 or 5xx.
